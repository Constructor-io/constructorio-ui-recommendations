# Usage Patterns

The Constructor Recommendations UI library is designed to be flexible by default and customizable when needed. Instead of enforcing a single way of working, it supports multiple usage patterns that let you adapt components to different use cases, styling approaches, and rendering requirements.

Each pattern represents a different level of control—from simple configuration to fully customized rendering—allowing you to choose the approach that best fits your use case without unnecessary complexity.

## 1. Default Usage

The simplest approach: pass required props and let the library handle everything.

```jsx
import CioRecommendations from '@constructor-io/constructorio-ui-recommendations';
import '@constructor-io/constructorio-ui-recommendations/styles.css';

function App() {
  return (
    <CioRecommendations
      apiKey="YOUR_API_KEY"
      podId="YOUR_POD_ID"
    />
  );
}
```
Use this when you want a fully functional recommendations carousel with minimal configuration.


## 2. Component Overrides

The `componentOverrides` prop allows you to customize specific parts of a component's rendering by providing custom content or render functions. This pattern is useful when you want to customize how a component (or part of it) is rendered without rewriting or wrapping the entire component.

### How It Works

Each override key accepts either:
- A static `ReactNode` to fully replace the rendered output
- A render function that receives the component's internal render props and returns a `ReactNode`

This enables both simple overrides (custom markup) and advanced ones (conditional rendering based on internal state).

### Example: Custom Pod Header

```jsx
import CioRecommendations from '@constructor-io/constructorio-ui-recommendations';

function App() {
  return (
    <CioRecommendations
      apiKey="YOUR_API_KEY"
      podId="YOUR_POD_ID"
      componentOverrides={{
        podHeader: {
          reactNode: ({ podHeader, podSubheader }) => (
            <div className="custom-header">
              <h2>{podHeader}</h2>
              {podSubheader && <p>{podSubheader}</p>}
            </div>
          ),
        },
      }}
    />
  );
}
```

> **Note:** For each component that supports component overrides, its documentation includes a dedicated reference listing all supported keys that can be passed to the `componentOverrides` prop, along with their corresponding render props.


## 3. Compound Components

The compound components pattern exposes a set of related subcomponents that work together under a shared parent context, allowing you to pass props directly to nested components rather than having the top-level component expose all child props. This keeps the API clean and makes it clear which props belong to which component.

### How It Works

1. The parent component provides shared context (state, API client, configuration)
2. Subcomponents are used directly in your JSX and receive their own props
3. Each subcomponent manages its own configuration instead of cluttering the parent's API

### Example: Custom Layout with Compound Components

```jsx
import CioRecommendations from '@constructor-io/constructorio-ui-recommendations';

function App() {
  return (
    <CioRecommendations apiKey="YOUR_API_KEY" podId="YOUR_POD_ID">
      {({ items }) => (
        <div className="custom-layout">
          <div className="header-section">
            <CioRecommendations.PodHeader />
          </div>
          <div className="carousel-section">
            <CioRecommendations.Carousel items={items} />
          </div>
        </div>
      )}
    </CioRecommendations>
  );
}
```

> **Note:** For each component that supports compound components, its documentation lists all available compound subcomponents, along with their expected hierarchy and usage rules.

## 4. Render Props

The render props pattern allows you to customize a component's rendering by passing a function as `children`. This function receives the component's internal state and helpers, giving you full control over what gets rendered while the component continues to manage its own behavior.

This pattern is ideal when customization requires dynamic logic or when you need to completely replace the default layout.

### How It Works

1. The component exposes a set of render props (state, callbacks, and helpers)
2. You provide a function that receives these props and returns a `ReactNode`
3. The component remains responsible for state management, accessibility, and behavior

### Example: Custom Grid Layout

```jsx
import CioRecommendations from '@constructor-io/constructorio-ui-recommendations';

function App() {
  return (
    <CioRecommendations apiKey="YOUR_API_KEY" podId="YOUR_POD_ID">
      {({ items, podId }) => (
        <div className="custom-grid">
          <h2>Recommendations from {podId}</h2>
          <div className="grid">
            {items.map((item) => (
              <div key={item.id} className="grid-item">
                <img src={item.imageUrl} alt={item.name} />
                <h3>{item.name}</h3>
                {item.price && <span>${item.price}</span>}
              </div>
            ))}
          </div>
        </div>
      )}
    </CioRecommendations>
  );
}
```

> **Note:** For each component that supports render props, its documentation clearly lists the available render props, including their types and intended usage.

## 5. Hooks for Full Control

For maximum flexibility, use the `useRecommendationResults` hook directly. This gives you complete control over the UI while the library handles data fetching, caching, and state management.

```jsx
import CioRecommendations, { useRecommendationResults } from '@constructor-io/constructorio-ui-recommendations';

function CustomUI() {
  const { status, data, message, refetch } = useRecommendationResults();

  if (status === 'fetching') return <LoadingSpinner />;
  if (status === 'error') return <ErrorMessage message={message} />;
  if (status === 'success') {
    return (
      <MyCustomComponent
        items={data.response.results}
        onRefresh={refetch}
      />
    );
  }
  return null;
}

function App() {
  return (
    <CioRecommendations apiKey="YOUR_API_KEY" podId="YOUR_POD_ID">
      {() => <CustomUI />}
    </CioRecommendations>
  );
}
```

## 6. Bundled Version (Vanilla JavaScript)

For non-React projects, the library provides a framework-agnostic bundle that can be used in any JavaScript project. The `CioRecommendations` function injects a complete recommendations UI into a specified DOM element.

### Options

| Option | Type | Description |
| ------ | ---- | ----------- |
| `selector` | `string` | **Required.** CSS selector for the container element where the UI will be injected |
| `apiKey` | `string` | **Required.** Your Constructor.io API key |
| `podId` | `string` | **Required.** The ID of the recommendations pod to display |
| `podSubheader` | `string` | Subheader text displayed below the pod title |
| `cioClientOptions` | `object` | Configuration options for the Constructor.io JS client |
| `parameters` | `object` | Additional parameters passed to the recommendations API (e.g., `numResults`, `filters`) |
| `itemFieldGetters` | `object` | Functions that map fields from your catalog to rendering fields |

For the full list of options, see [CioRecommendations Props](./?path=/docs/components-ciorecommendations--docs).

### HTML Setup

```html
<!-- Add a container element -->
<div id="recommendations-container"></div>

<!-- Include the bundle -->
<script type="module">
  import CioRecommendations from '@constructor-io/constructorio-ui-recommendations/constructorio-ui-recommendations-bundled';

  CioRecommendations({
    selector: '#recommendations-container',
    apiKey: 'YOUR_API_KEY',
    podId: 'YOUR_POD_ID',
  });
</script>
```

## Choosing the Right Pattern

| Pattern             | When to Use                                                                 |
| ------------------- | --------------------------------------------------------------------------- |
| Default Usage       | Standard recommendations carousel with minimal customization                |
| Component Overrides | Customize specific parts (header, cards) while keeping the overall structure |
| Compound Components | Custom layout with direct control over subcomponent props                   |
| Render Props        | Complete control over layout while keeping data fetching managed            |
| Hooks               | Maximum flexibility, custom state handling, or integration with other systems |
| Bundled Version     | Non-React projects or vanilla JavaScript applications                       |
